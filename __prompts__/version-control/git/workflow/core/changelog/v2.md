## 3. Detailed Version Entries
[INTENT: SPECIFICATION]

### 3.1 Version `2.5.0`
[INTENT: SPECIFICATION]

Bind the pre-push birth recognition into the core contract: the `validate
pre-push` register row extends its result boundary with the state-based
recognition of the governed remote birth through the shared birth-topology
predicate, the birth-family paragraph binds the recognition with the bypass
prohibition, the symbol-registry birth area carries the recognition surface,
and the audit format gains the pre-push recognition record. Full
classification, change units, migration impact, and commit alignment live in
`changelog/v2/v2-5-0.md`.

### 3.2 Version `2.4.0`
[INTENT: SPECIFICATION]

Bind the governed birth-lifecycle endpoints into the core contract: the
`workflow bootstrap recover` register row and the `workflow bootstrap
publish` register row, the symbol-registry extension of the birth area, the
branch-context matrix row for the shared-line publish-resume, and the
birth-mode parameter of the bootstrap audit record. Full classification,
change units, migration impact, and commit alignment live in
`changelog/v2/v2-4-0.md`.

### 3.3 Version `2.3.1`
[INTENT: SPECIFICATION]

Modularize the core-invariants detail surface: the TOC keeps the scope
overview, the invariant register with leaf links, the package description
index, and the execution context, while all thirteen INV unit details
migrate verbatim into per-unit leaves under `description/core-invariants/`.
Full classification, change units, migration impact, and commit alignment
live in `changelog/v2/v2-3-1.md`.

### 3.4 Version `2.3.0`
[INTENT: SPECIFICATION]

Bind the lane worktree requirement and the lane-aware acquisition base into
the core contract: the branch-context matrix wires the hotfix and release
lane families to the task-worktree requirement with the fail-closed
enforcement statement, and the worktree acquisition sentence binds the
lane-aware base with binary-help ownership of the endpoint form. Full
classification, change units, migration impact, and commit alignment live in
`changelog/v2/v2-3-0.md`.

### 3.5 Version `2.2.0`
[INTENT: SPECIFICATION]

Project the landed worktree lifecycle surface into the core contract: the
proven-completion prune endpoint register row and the task-worktree-registry
correction of the allocation-inventory enumeration. Full classification,
change units, migration impact, and commit alignment live in
`changelog/v2/v2-2-0.md`.

### 3.6 Version `2.1.0`
[INTENT: SPECIFICATION]

Bound the task-bound worktree convention into the core contract: the
actor-agnostic worktree rule, the worktree lifecycle endpoint register, the
publish-return worktree special case, and the matrix wiring for the fresh
detached task worktree. Full classification, change units, migration impact,
and commit alignment live in `changelog/v2/v2-1-0.md`.

### 3.7 Version `2.0.0`
[INTENT: SPECIFICATION]

Bound the file-based message transport: multi-line message parts (commit
bodies and pull-request descriptions) cross the CLI boundary exclusively
through message files passed by absolute path — an existing plain UTF-8 text
file of at most 1 MiB whose content is carried verbatim — the string body and
message flags are withdrawn, the temp-file creation discipline is owned by
the core as contract section [6.4.6], and the prohibition list excludes the
temp area as an information source. Full classification, change units,
migration impact, and commit alignment live in `changelog/v2/v2-0-0.md`.
