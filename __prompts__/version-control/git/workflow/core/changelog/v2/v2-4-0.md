### 3.1 Version `2.4.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The change is a backward-compatible workflow capability addition: two new endpoint-map rows extend the repository-birth family, the birth area of the symbol registry is extended without adding a symbol, the branch-context matrix gains one row for the shared-line publish-resume, and the bootstrap audit record gains its birth-mode parameter. No existing row is removed, renamed, or reordered; no invariant, guard, or safety contract changes. |

**Change Units**

|| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
||----|----------|----------|---------|----------------|----------------------|
|| CORE-154 | `feat` | no | Register the `workflow bootstrap recover` endpoint: the governed pre-birth recovery restores the proven pre-birth state (empty index, no references) of an unborn repository whose index or references carry a foreign or aborted pre-staging state — the remediation capability of the `WORKTREE_NOT_CLEAN` preflight rule — fail-closed with `REPOSITORY_ALREADY_BORN` on born repositories, an untouched working tree, read-back evidence, and idempotent no-op on a clean unborn state. | `prompt.md` (endpoint register [5.5], symbol registry [0.3], branch-context matrix [4.3], audit record [9]) | registry coverage alignment |
|| CORE-155 | `feat` | no | Register the `workflow bootstrap publish` endpoint: the governed publication resume re-proves the complete birth topology (exactly one commit, `main` and `develop` on the shared genesis revision, verified genesis signature, materialized hook boundary, bound remote) before the separately confirmed push of exactly the born shared lines, fail-closed with `BIRTH_STATE_INVALID` outside the proven state. | `prompt.md` (endpoint register [5.5], symbol registry [0.3], branch-context matrix [4.3], audit record [9]), `description/endpoint-registry.md` | registry coverage alignment |

**Migration / Consumer Impact**

No migration required. The two new register rows are additive; every
pre-existing row, invariant, symbol, and audit record shape stays unchanged
except for the additive `mode` parameter of the bootstrap audit record.
Consuming agents derive the invocation forms from the binary's current help
at runtime, so no flag knowledge is carried by this change.
