### 3.1 Version `2.7.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The change is a backward-compatible workflow capability binding: one new endpoint-register row extends the governed topology with the canonical message-file constructor, contract section [6.4.6] replaces its agent-side creation mechanics with the constructor-usage discipline while keeping every prohibition (orientation ban, single use, content-contract independence) in force, the registry coverage and the adapter coverage class gain one enumeration line each, and the prohibition list gains one bullet. No existing row, invariant, guard, or safety contract is removed, renamed, or reordered; the removed instructions (UUID naming, pre-existence probe, context-tool-first write order) are superseded by the platform primitive the endpoint now owns, so no lawful path is lost. |

**Change Units**

|| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
||----|----------|----------|---------|----------------|----------------------|
|| CORE-160 | `feat` | no | Bind the `message scaffold` register row into the endpoint registry: an E2 command that constructs the governed message file in the operating-system temporary area through the atomic collision-safe platform primitive, pre-fills the canonical layout from the registers the help and validators render from, reports the absolute path, and is a construction aid never a gate — the content contract stays owned by validation. | `prompt.md` (endpoint register [5.2]) | registry coverage alignment |
|| CORE-161 | `feat` | no | Rewrite the message-transport discipline of [6.4.6] from agent-side creation to constructor usage: message files originate exclusively from `message scaffold`; the agent edits the reported path in place and passes it unchanged; the naming mechanics and the proactive existence check are removed because the primitive guarantees both; the orientation prohibition and the single-use rule carry forward unchanged; hand-created message files become a named contract violation in the prohibition list. | `prompt.md` ([6.4.6], [10]) | invariant alignment |
|| CORE-162 | `docs` | no | Project the constructor into the metadata surfaces: the registry coverage enumeration and the current-state paragraph of the endpoint-registry detail surface, and the adapter-side endpoint coverage class of the guarantees surface. | `description/endpoint-registry.md`, `description/guarantees-and-endpoint-coverage.md`, `DESCRIPTION.md` | registry coverage alignment |

**Migration / Consumer Impact**

No migration required. Every consuming agent keeps composing message content under [6.4]; only the origin of the file changes from agent-side creation to the governed constructor. Agents that previously created files by hand lose the (previously tolerated) manual path — the constructor is now the single lawful origin, and the removed existence-probe instruction contradicted nothing an agent had to keep.
