## 3. Detailed Version Entries

### 3.1 Version `2.1.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The worktree convention binding is additive: the detached-state matrix gains a legitimate pre-start row for fresh task worktrees while every other detached or unknown state keeps its blocked behavior, the register entries describe implemented binary endpoints, and the publish-return gains an honest worktree special case. No prior workflow capability, authority, or safety contract is withdrawn. |

**Change Units**

|| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
||----|----------|----------|---------|----------------|----------------------|
|| CORE-142 | `contract` | no | Bind the actor-agnostic worktree rule at task intake: a fresh detached task worktree created for a ticket is a legitimate pre-start context for every actor executing ticket work, acquired through the governed `workflow worktree start` endpoint; the sanctioned first mutation inside the worktree is the governed `workflow ticket start` dispatch; every other detached or unknown state stays blocked. | `prompt.md` | `description/endpoint-registry.md` REG-001 |
|| CORE-143 | `runtime` | no | Register the worktree lifecycle endpoints: `workflow worktree start` (E1), `workflow worktree list` (RO), and `workflow worktree remove` (E1), dormant until the binary help offers them and active with the implemented binary release. | `prompt.md` | `description/endpoint-registry.md` REG-001 |
|| CORE-144 | `runtime` | no | Bind the publish-return worktree special case: a linked task worktree checkout does not participate in the governed return to the integration line when that line is bound in the primary checkout; the return status is reported honestly and the pull request stays untouched. | `prompt.md` | `description/core-invariants.md` post-publication transition |
|| CORE-145 | `runtime` | no | Wire the branch-context matrix: the specific row for a fresh detached task worktree takes precedence before the blocked catch-all, the E1 workflow family enumeration extends with `worktree`, and the embargo allowlist names the governed worktree acquisition explicitly. | `prompt.md` | `description/core-invariants.md` state machine |
|| CORE-146 | `docs` | no | Synchronize the metadata surfaces with the implemented capability: the root and family changelog TOCs, this version leaf, the endpoint-registry coverage, and the root description index. | `CHANGELOG.md`, `changelog/v2.md`, `changelog/v2/v2-1-0.md`, `description/endpoint-registry.md`, `DESCRIPTION.md` | full metadata alignment |

**Migration / Consumer Impact**

No migration required. Consumers without the worktree convention keep the
generic register entries dormant through the help-first contract; consumers
of the implemented binary acquire task worktrees through the governed
endpoint and start tickets inside the worktree.
