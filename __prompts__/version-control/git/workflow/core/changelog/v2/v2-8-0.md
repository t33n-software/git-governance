## 3. Detailed Version Entries
[INTENT: SPECIFICATION]

### 3.1 Version `2.8.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The change is a backward-compatible phase-boundary clarification: every prohibition, guard, and safety contract stays in force verbatim — the mutation embargo remains repository-scoped, absolute, and unweakened — while read-only discovery, injected-prompt report obligations, and writes to targets outside governed repositories move explicitly ahead of the worktree acquisition. No endpoint, authority, or refusal behavior is removed, renamed, or reordered. Agents that already report before implementing keep working unchanged; the observed inversion (worktree proposal first, report demoted to a follow-up) becomes a named prohibition instead of an implicit wrapper side effect. |

**Migration / Consumer Impact**

No migration required. Every consuming agent keeps the full mutation embargo; only the ordering of read-only work and report obligations becomes explicit. The source-repository adapter mirrors the exception in its activation contract and pre-action embargo (adapter version `1.8.0`) so wrapper machinery can no longer displace injected prompt contracts.
