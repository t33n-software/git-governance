## 3. Detailed Version Entries
[INTENT: SPECIFICATION]

### 3.1 Version `2.10.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The change is a backward-compatible refinement of the help-first runtime contract: the absolute per-invocation duty is kept verbatim for every endpoint that carries a state effect or starts a lane, and it is relaxed to one anchoring per opened contract epoch only for read-only idempotent endpoints, whose repeated help dispatches carried context cost without correctness gain. Every invalidation that previously reopened the whole duty still reopens it per [0.2.2]; no state, guard, proof, gate, or publication boundary is removed, renamed, or weakened. An agent following the previous contract literally never violates the new one. |

**Migration / Consumer Impact**

No migration required. Agents that anchor per call anyway remain fully compliant. Agents that want the epoch economy bind the invalidation list of [0.2.2] as the only way an epoch closes; the affectedness-guard globs of the repository name the CLI-source trigger explicitly, and the adapter binds the same closure through its invalidation section. Consuming repositories pick the change up with their next core load; the binary itself is untouched, so every flag contract stays help-owned.
