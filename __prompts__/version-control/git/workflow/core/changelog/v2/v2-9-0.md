## 3. Detailed Version Entries
[INTENT: SPECIFICATION]

### 3.1 Version `2.9.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The change is a backward-compatible strengthening of the discovery phase-entry binding: the existing proof `shared_line_refresh_checked` moves from a transition-side condition to a check bound before the first read of the local shared-line tree, and the existing `branch refresh-shared-lines` endpoint gains the discovery entry as a named trigger. No state, endpoint, guard, proof, or prohibition is removed, renamed, or weakened; the mutation embargo, the report-before-worktree sequencing, and every freshness decision bound to fetched remote-tracking bases stay verbatim. Agents that already refreshed before reading are unaffected; the observed residue (read-only analysis on a stale local tree) becomes impossible by contract. |

**Change Units**

|| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
||----|----------|----------|---------|----------------|----------------------|
|| CORE-169 | `docs` | no | Bind the freshness proof to the `DISCOVERY_AND_TASK_RESPONSE` phase entry: the first read access to the local shared-line tree requires the prior `shared_line_refresh_checked` proof; the check verifies the checked-out integration line against its fetched remote-tracking reference and restores freshness through the governed capability on lag, so check and restoration are one entry action. | `prompt.md` ([2.1]) | invariant alignment |
|| CORE-170 | `docs` | no | Re-annotate the `shared_line_refresh_checked` proof: entry timing of the discovery phase replaces the read-only retrospective description; the acquisition-base dependency clause stays. | `prompt.md` ([2.3]) | invariant alignment |
|| CORE-171 | `docs` | no | Extend the `branch refresh-shared-lines` register trigger with the discovery-entry binding: the freshness proof at phase entry whenever the local shared-line tree is read, alongside the pre-existing downstream-reader trigger. | `prompt.md` ([5.2]) | registry alignment |

**Migration / Consumer Impact**

No migration required. Consuming agents now bind the governed refresh as the first action of any discovery that reads the local shared-line tree instead of treating a stale local checkout as analysis truth; the documented posture that a lagging local checkout is harmless for governed mutations stays unchanged.
