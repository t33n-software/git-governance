### 3.1 Version `2.0.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `major` |
|| Breaking Change | `yes` |
|| Rationale | The CLI contract change is incompatible by design: the inline string flags for commit bodies, merge bodies, the scratch squash transfer body, pull-request descriptions, and the complete commit message are withdrawn in favor of file-path flags, so every invocation that passed message content inline must switch to message files. The core change re-anchors the transport contract in [6.4.5] and [8.1], owns the new message-file creation discipline [6.4.6], and extends the prohibition list; the CLI flags, value domains, and validation formats stay binary-owned and are discovered through help. |

**Migration / Consumer Impact**

Breaking for every consumer that passed message content inline: commit bodies
(`--body`), merge bodies (`--merge-body`), the scratch squash transfer body
(`--commit-body`), pull-request descriptions (`--body` on the publish
endpoints), and the complete commit message (`commit validate --message`) are
withdrawn. Each surface now carries a file-path flag (`--body-file`,
`--merge-body-file`, `--commit-body-file`) whose help renders the
absolute-path, plain-UTF-8, 1 MiB contract from the canonical value-domain
register; `commit validate --message-file` keeps its repository-file semantics
for the commit-msg hook. Consuming agents derive the invocation from the
current endpoint help and create message files through the [6.4.6]
discipline.
