[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |

|| Rationale | The change is an additive contract registration of a capability the binary now implements. **Change Units**

|| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
||----|----------|----------|---------|----------------|----------------------|
|| CORE-111 | `registry` | no | Extended the `branch sync-base` registry row to bind the governed re-entry into its conflict-paused rebase or merge operation, with quality re-verified after mutation and after resume. | `prompt.md` | `description/endpoint-registry.md` section 3.1 |
|| CORE-112 | `contract` | no | Bound conflict-protocol step 6 to the concrete governed resume entry points: the resume mode of `branch sync-base` for rebase or merge operations paused by that endpoint, and the owning workflow's resume entry for workflow-paused operations. | `prompt.md` | `description/core-invariants.md` section 3.4 |
|| CORE-113 | `metadata` | no | Modularized the description surface into the root TOC plus the `description/` package and the changelog surface into the root ledger plus the `changelog/v1` family TOC with one concrete leaf per released version, as required by the shared metadata threshold model. | `DESCRIPTION.md`, `description/`, `CHANGELOG.md`, `changelog/` | Root TOCs created |

**Migration / Consumer Impact**

No migration required. Consuming agents and adapters read the same core prompt; the metadata package topology changes only the documentation layout. The registered resume capability is available with the binary whose help exposes it; against a binary whose help does not expose the resume mode, the conflict protocol blocks instead of falling back to raw Git.
