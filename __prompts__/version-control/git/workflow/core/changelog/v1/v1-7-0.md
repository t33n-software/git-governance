## 3. Detailed Version Entries
[INTENT: SPECIFICATION]

### 3.1 Version `1.7.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The change is an additive endpoint-map, state-classification, task-pattern, symbol, and prohibition contract. Every pre-existing workflow rule, state, proof, endpoint row, symbol, decision row, and prohibition is preserved in substance; the new `unborn` branch context only adds a classification for a repository state the guard previously misclassified as a shared line. |

**Change Units**

|| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
||----|----------|----------|---------|----------------|----------------------|
|| CORE-127 | `contract` | no | Register the governed repository birth: the endpoint registry binds `workflow bootstrap` as the level-1 workflow and the only governed creation path of `main` and `develop`, with its result boundary (signed genesis commit on `main`, `develop` from the same revision, installed hook boundary, genesis evidence record, separately confirmed `--push` publication). | `prompt.md` | `description/endpoint-registry.md` section 3.1 |
|| CORE-128 | `runtime` | no | Add the `unborn` branch context: a repository without commits and without references never activates the mutation embargo, because no shared line exists to protect; the initial content set is the birth's input, and the entry matrix routes `unborn` birth tasks to `workflow bootstrap` while every other workflow stays blocked until the birth. | `prompt.md` | `description/core-invariants.md` section 3.12 |
|| CORE-129 | `contract` | no | Add the `bootstrap` task pattern (the birth of an unborn repository) with no provider effect, and the repository-birth area symbol 🐣 in the status registry. | `prompt.md` | `description/core-invariants.md` section 3.12 |
|| CORE-130 | `contract` | no | Bind the birth prohibitions: never birth a repository through raw Git, `branch create`, or `commit create`; never create `main` or `develop` outside the governed birth; never treat the unborn state as a shared-line embargo case or start another workflow on an unborn repository. | `prompt.md` | `description/security-and-evidence.md` section 3.1 |

**Migration / Consumer Impact**

No migration required. Consuming agents and adapters read the same core
prompt; the registered capability activates through the existing help-first
runtime contract, and an installed binary that predates the endpoint simply
offers no such help entry, which keeps the reference truthful on older
installations.
