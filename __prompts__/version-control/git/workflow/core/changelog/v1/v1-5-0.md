### 3.1 Version `1.5.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The change is an additive intake-governance and publication-expectation contract. Every pre-existing workflow rule, state, proof, endpoint row, symbol, decision row, and prohibition is preserved in substance; the branch-context check gains one probe step, the continuation decision gains one completed-handoff row, and the publication section gains the post-publish workspace expectation without weakening any existing gate, and no flag, regex, limit, or runtime mode enters the prompt. |

**Change Units**

|| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
||----|----------|----------|---------|----------------|----------------------|
|| CORE-123 | `contract` | no | Bound the completed-pull-request branch probe: an official working branch is probed for its pull-request state through the existing discovery capability chain before any continuation decision, binding `current_branch_pr_state` and the `current_branch_pr_state_checked` proof; an open or merged pull request marks the branch as a completed handoff that starts no continuation analysis for a new independent task, while a task that recognizably continues the open pull request's scope remains a valid continuation and an unavailable probe preserves the previous decision path. | `prompt.md` | `description/core-invariants.md` section 3.11 |
|| CORE-124 | `contract` | no | Bound the post-publication workspace expectation: after a successful publish run with a created pull request, the local workspace is expected back on the `develop` integration line through the governed return switch of the binary; the agent verifies that end state as the completion signal and never as a new task source, and any deviation re-enters the continuation rules of the intake decision. | `prompt.md` | `description/core-invariants.md` section 3.11 |

**Migration / Consumer Impact**

No migration required. Consuming agents and adapters read the same core prompt; the probe activates through the existing discovery capability chain, and the continuation question for branches without pull-request evidence is preserved unchanged.
