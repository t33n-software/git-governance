### 3.1 Version `1.6.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The change is an additive endpoint-map and invariant-binding contract. Every pre-existing workflow rule, state, proof, endpoint row, symbol, decision row, and prohibition is preserved in substance; the endpoint registry gains exactly one bounded-command row, and the integration-line staleness invariant keeps its conditional form while naming the register that binds the capability, and no flag, regex, limit, or runtime mode enters the prompt. |

**Change Units**

|| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
||----|----------|----------|---------|----------------|----------------------|
|| CORE-125 | `contract` | no | Register the on-demand shared-line refresh: the endpoint registry binds `branch refresh-shared-lines` as a level-2 bounded command for an explicitly required freshness of local shared-line checkouts — for example when a downstream process reads the local tree directly — with its result boundary of fast-forward-only, fail-closed, no remote mutation, no checkout switch, and no line creation. | `prompt.md` | `description/endpoint-registry.md` section 3.1 |
|| CORE-126 | `contract` | no | Bind the integration-line staleness invariant to the registered capability: a lagging local integration-line checkout remains expected and harmless and is never a defect, a task source, or a repair trigger, but an explicitly required refresh is now bound to the registry-owned governed capability of the binary, so long as the current help offers it; the help-first conditionality keeps older installed binaries truthful instead of blocked by a reference to a capability they do not carry. | `prompt.md` | `description/endpoint-registry.md` section 3.1 |

**Migration / Consumer Impact**

No migration required. Consuming agents and adapters read the same core prompt; the registered capability activates through the existing help-first runtime contract, and an installed binary that predates the endpoint simply offers no such help entry, which keeps the conditional invariant truthful on older installations.
