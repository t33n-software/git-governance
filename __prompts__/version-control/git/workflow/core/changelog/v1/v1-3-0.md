## 3. Detailed Version Entries
[INTENT: SPECIFICATION]

### 3.1 Version `1.3.0`
[INTENT: SPECIFICATION]

**Classification**

|| Field | Value |
||-------|-------|
|| Semver Class | `minor` |
|| Breaking Change | `no` |
|| Rationale | The change is an additive content-governance contract. Every pre-existing workflow rule, state, proof, endpoint row, symbol, and prohibition is preserved in substance; the new proofs `commit_content_verified` and `pr_description_verified` extend the evidence model without weakening any existing gate, and the publish checklist gains one content item without removing any. |

**Change Units**

|| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
||----|----------|----------|---------|----------------|----------------------|
|| CORE-114 | `contract` | no | Added the commit content architecture: subject carries the one-sentence intent, the body carries what the diff cannot express (intent, behavioral scope, touched invariants or contracts, verification evidence, risks), and the body is the relevance filter of the commit history for later agents (filter before fetch). | `prompt.md` | `description/core-invariants.md` section 3.10 |
|| CORE-115 | `contract` | no | Added the binding body-mandate decision matrix: bodies are the default; hotfix lanes, release/support lanes, breaking markers, and scratch squash transfers always require one; behavior and structure families require one except for provably trivial units; only provably trivial `style`/`chore` units may omit, audited as `omitted-justified`. | `prompt.md` | `description/core-invariants.md` section 3.10 |
|| CORE-116 | `contract` | no | Added content anti-patterns (diff narration, filler text, content not evidenced by the staged paths, secrets) and the `commit_content_verified` proof with help-first transport and a fail-closed named gap when the binary exposes no body transport. | `prompt.md` | `description/core-invariants.md` section 3.10 |
|| CORE-117 | `contract` | no | Added the pull-request description architecture: the description carries the integration layer (overall intent, scope and non-goals, series map as navigation, aggregate risk and rollback reference, lane context, verification strategy and review focus) and never replicates commit content; added the `pr_description_verified` proof and fail-closed reporting when no publish endpoint exposes a description transport. | `prompt.md` | `description/core-invariants.md` section 3.10 |
|| CORE-118 | `evidence` | no | Extended the minimum proof ledger with `commit_content_verified` and `pr_description_verified`, the publish checklist with the description item, the completion answer with the description outcome, and the audit records with `body=<present\|omitted-justified>` and `pr_body=<transported\|gap\|not_required>`; added the matching content prohibitions. | `prompt.md` | `description/core-invariants.md` section 3.10 |
|| CORE-119 | `contract` | no | Completed the commit content contract so agents make only generic content decisions: the subject formulation contract binds language (English), imperative mood, behavior-over-file naming, and forbidden filler forms; the canonical body layout binds the category order (Motivation, Behavioral Change, Contracts and Invariants, Verification, Risks and Follow-ups) with a short-form rule; the executable acceptance gate makes `commit_content_verified` falsifiable through five canonical questions answerable without the diff. | `prompt.md` | `description/core-invariants.md` section 3.10 |
|| CORE-120 | `contract` | no | Bound the pull-request description as mandatory, never optional: every pull request crosses a protected shared line, so the review gate's information carriers are deterministic; the mandate covers presence and contract fidelity, not length; the canonical section order is Summary, Scope and Non-Goals, Commit Series (navigation only), Risk and Rollback, Verification and Review Focus. | `prompt.md` | `description/core-invariants.md` section 3.10 |

**Migration / Consumer Impact**

No migration required. Consuming agents and adapters read the same core prompt; the content contract activates through the existing help-first transport rule. Against a binary whose publish help exposes no pull-request description transport, the agent reports the named gap instead of falling back to an external PR CLI, raw provider calls, or manual web edits.
