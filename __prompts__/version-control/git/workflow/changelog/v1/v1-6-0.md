### 3.1 Version `1.6.0`
[INTENT: SPECIFICATION]

**Classification**

| Field | Value |
|-------|-------|
| Semver Class | `minor` |
| Breaking Change | `no` |
| Rationale | The change is a backward-compatible workflow capability delivery: the branch-hygiene evidence capability, the two governed endpoints, and the three new stable failure codes are additive; every pre-existing use case, failure code, and CLI surface stays unchanged. The hygiene endpoints are repository-surface operations outside the task-worktree requirement, and the deletion runs only under the proven hybrid guard matrix, so no governed consumer path changes. |

**Change Units**

| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
|----|----------|----------|---------|----------------|----------------------|
| CHG-601 | `feat` | no | Added the branch-ahead evidence capability: the optional `BranchAheadCounter` port counts the commits a local branch carries that its selected remote-tracking base does not, the Git adapter measures it through `rev-list --count` with a platform-sized parse, and the five-case whitebox matrix binds the evidence contract. | `internal/application/port/port.go`, `internal/adapters/gitcli/repository.go`, `internal/adapters/gitcli/repository_test.go` | metadata architecture alignment |
| CHG-602 | `feat` | no | Added the branch-hygiene use cases: the single-branch removal and the evidence-based discovery-and-batch prune classify every local official working branch against the hybrid guard matrix — the newest provider pull-request record, the remote branch-cleanup obligation, the checkout guard, and the null-ahead measurement against the recorded lane base — and three stable failure codes carry the protection classes (`BRANCH_AHEAD_UNMERGED`, `BRANCH_CHECKED_OUT`, `BRANCH_PULL_REQUEST_OPEN`). | `internal/application/workflow/branch_hygiene.go`, `internal/application/workflow/branch_hygiene_test.go`, `internal/domain/problem/problem.go` | metadata architecture alignment |
| CHG-603 | `feat` | no | Exposed the governed workflow endpoints: `workflow branch remove` and `workflow branch prune` carry the house CLI contracts — the register-bound branch flag, the mutation confirmation, the dry-run plan, and the non-interactive confirmation — the runtime composition binds the service with the provider inventory capability, and the CLI contract tests cover both endpoints. | `internal/bootstrap/branch_hygiene_commands.go`, `internal/bootstrap/branch_hygiene_commands_test.go`, `internal/bootstrap/runtime.go`, `internal/bootstrap/workflow_commands.go` | metadata architecture alignment |
| CHG-604 | `docs` | no | Projected the branch-hygiene endpoint family into the workflow core: core version `2.6.0` records the endpoint register rows, the execution-level enumeration, the embargo-allowlist bullet, and the task-worktree enforcement exception. | `core/prompt.md` | metadata architecture alignment |

**Migration / Consumer Impact**

No migration required. The two new endpoints are additive and discoverable
through the binary's current help; every pre-existing endpoint, failure
code, and report shape stays unchanged. Compositions whose Git adapter lacks
the ahead measurement fail closed with the named capability.
