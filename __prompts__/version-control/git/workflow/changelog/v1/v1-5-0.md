### 3.1 Version `1.5.0`
[INTENT: SPECIFICATION]

**Classification**

| Field | Value |
|-------|-------|
| Semver Class | `minor` |
| Breaking Change | `no` |
| Rationale | The enforcement extends the already-bound task-binding convention to every local working-branch lane and makes it programmatically fail-closed; the sanctioned workflow composition always hosts lane work in task worktrees, so no governed consumer path changes. Capability-less server compositions keep the documented legacy behavior, and the failure vocabulary is reused without new codes. |

**Change Units**

| ID | Category | Breaking | Summary | Affected Files | Description Alignment |
|----|----------|----------|---------|----------------|----------------------|
| CHG-501 | `feat` | no | Required task worktrees across the eight lane dispatches: hotfix start, release stabilization, promotion and backmerge preparation, single-commit and manifest propagation, and both base alignments fail closed outside a linked task worktree before any branch or worktree mutation. | `internal/application/workflow/release.go`, `internal/application/workflow/promotion_alignment.go`, `internal/application/workflow/reconciliation_alignment.go` | `description/guarantees-and-endpoint-coverage.md` GUA-001 |
| CHG-502 | `feat` | no | Extracted the shared lane-aware task-binding guard: ticket start wraps it with the develop base, and the lane dispatches measure the detached pre-start form against each lane's own acquisition base — the affected protected line, the frozen release line, and the propagation target line. | `internal/application/workflow/worktree.go` | `description/guarantees-and-endpoint-coverage.md` GUA-001 |
| CHG-503 | `feat` | no | Added the whitebox enforcement matrix: the gate on all eight dispatches, the lane-base measurement in the detached pre-start form, the legacy behavior without the worktree capability, and the shared guard's drift binding. | `internal/application/workflow/release_lane_worktree_test.go` | `description/guarantees-and-endpoint-coverage.md` GUA-001 |
| CHG-504 | `docs` | no | Projected the lane worktree governance into the workflow core: core version `2.3.0` records the branch-context matrix wiring for the lane families and the lane-aware acquisition-base formulation. | `core/prompt.md` | `description/guarantees-and-endpoint-coverage.md` GUA-001 |

**Migration / Consumer Impact**

No migration required for the governed workflow: the sanctioned composition
already acquires lane work through the governed worktree lifecycle. Direct
dispatches from the primary checkout now fail closed by design; the failure
records point to the governed worktree acquisition.
